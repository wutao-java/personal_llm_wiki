# data.js 数据契约 · 套展厅模板

## 何时使用

范式已选定，要把用户项目的真实图谱数据接进去、产出升级后的可视化页时。这是核心动词（接入/优化）的执行体。**还没选范式**就先走 kg-paradigm-selection；**上游是 GraphRAG/GBrain 产物**先走 kg-upstream-adapters 做形态映射，再回到本能力落 data.js。

## 核心契约

星图馆的心法是"**同一份数据，多种投影**"：所有展厅共用一个 data.js，每种可视化只是同一张图的不同几何投影。**数据层只改 data.js 这一个文件**，展厅的渲染代码原样复用。

但**接入 ≠ 只换数据**。交付进用户项目前必须做满三层落地——数据（data.js）、文案（页面话术）、主题（视觉基调），后两层见核心流程第 4/5 步。模板自带的文字是"星图馆演示语境"（AI 领域样例图 + 展馆隐喻），带着它们上线等于把别人的展签挂进用户的项目。

`window.KG` 必含字段（对照 assets/data.js 实物）：

```
window.KG = {
  DOMAINS:   [{id, name, en, color}]              // 分类/社区，≤8 个（调色板只有 8 色）
  nodes:     [{id, name, domain, hub, degree, index}]
  links:     [{source, target, weight}]           // id 引用
  byId:      {id → node}                          // Object.fromEntries 建，附带 index 回填
  hierarchy: {name, children:[domain{children:[concept]}]}  // 04/08 展厅用
  mulberry32(seed)                                // 种子随机，保证布局可复现
}
```

## 核心流程

1. **复制模板**：从 assets/ 把选定展厅 HTML + data.js + shared.css 复制进用户项目（不动项目原有业务文件）。
2. **只改 data.js**：把真实图谱改写成上述契约。要点：
   - 必须用**种子随机 mulberry32**，不要 `Math.random()`——否则每次刷新布局不同、无法调试复现。
   - **预计算 degree**（度数）：多个展厅靠它定节点大小，缺了节点尺寸全一样。
   - DOMAINS ≤ 8；边去重（无向图 `a<b` 做 key）；byId 建索引并回填 `index`。
   - 需要 04 光纤束 / 08 双曲空间的，补 `hierarchy` 两层结构（域→概念）。
3. **对账**：生成后核对 `KG.nodes.length` / `KG.links.length` 与源数据节点/边数一致——数量对不上就是漏映射或重复。
4. **文案落地（必做，不许保留模板话术）**：模板 HTML 里所有面向用户的文字逐条改写成
   **项目自己的业务说法**——标题/副题（如"辉光深空"→ 项目图谱的真实名目）、操作按钮
   （模板的"手动驾驶/自动巡航/经典视图/粒子流"等馆内隐喻必须换成项目语气，如
   "手动视角/自动环游"或更贴业务的说法）、图例分类名、右下读数单位、tooltip、快捷键提示。
   改完 grep 自查：`展厅|星图馆|EXHIBIT|手动驾驶|自动巡航|经典视图` 在交付页面中零命中
   （数据侧同理：模板样例的"8 大领域/120 节点"字样不得残留）。
5. **主题落地（决策点，不许默认硬套）**：看用户项目有没有既定设计系统/品牌色——
   - 有 → 适配：改 shared.css 的 surface 底色、字体、DOMAINS 主色向项目基调靠拢；
     **新配色必须重跑 `node scripts/validate_palette.js` 四项机检**（主题可换，机检不豁免），
     bloom/发光参数仍从安全起点调。
   - 没有或用户没说 → **问一句**"保留深空天文台主题，还是贴你项目的视觉基调？"再动手；
     深空主题是本包默认美学，但它是选项不是强制。
6. **校验→修复→重试**：套模板起服务看渲染；节点大小全一样→补 degree；刷新布局变→换回 mulberry32；跑通后进 kg-verification-loop 做截图验证闭环（验证项含第 4 步的文案 grep 自查）。

## 反模式

- ❌ 绕过 data.js 契约把数据散写进展厅 HTML——"同一份数据，多种投影"即失效，换个范式就得重写数据。
- ❌ 用占位假数据交差——必须消费真实上游产物，节点/边数与源可对账。
- ❌ 用 `Math.random()` 代替 mulberry32——刷新即变布局，用户报"每次长得不一样"无法调试。
- ❌ 漏算 degree——多个展厅靠它定节点大小，缺了尺寸全一样、枢纽淹没在概念里。
- ❌ **模板文案原样上线**——"手动驾驶/自动巡航"这类星图馆演示话术出现在用户业务项目里（2026-07-14 实装实测的真实事故），数据适配了、语境没适配，用户一眼识破"这是模板"。
- ❌ **主题硬套**——不问项目视觉基调直接上深空主题；或反过来换了主题却跳过 validate_palette 机检。
