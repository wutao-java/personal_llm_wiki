# 十范式选型 · 默认弹画廊让用户亲选

## 何时使用

用户点名要可视化/美化图谱、问"哪种展示适合我的数据"、或要求"弹画廊让我选一种"时。这是核心工作流第一步。**用户已点名范式**（如"就用辉光深空 3D"）则跳过选型直接进接入。

## 核心流程

1. **先起画廊，不替用户定审美**：在装了本包的项目里起本地服务，打开 assets/index.html 星图馆画廊，让用户浏览十范式卡片并亲自点名要接入的范式。
   ```bash
   # 验证用 http，不用 file://（方法论 §六-2）
   cd <本包 assets 目录> && python3 -m http.server 8080
   # 然后打开 http://localhost:8080/index.html
   ```
2. **用户拿不定时，按决策链引导**（问题→五大家族→范式），不要直接甩一个"我觉得好看的"：

   | 用户想回答什么问题 | 家族 | 范式（assets 文件） |
   |---|---|---|
   | 万级~百万级节点看全貌 | 力导向 | 01 GPU 星云（01-cosmos.html） |
   | 数百节点 + 要炫的叙事感 | 力导向 | 02 辉光深空 3D（02-bloom3d.html） |
   | 概念随时间如何长出来 | 力导向 | 07 时间演化（07-temporal.html，叙事性最强） |
   | 降维/嵌入后的语义分布地貌 | 空间嵌入 | 03 语义地形图 / 09 语义山脉 3D |
   | 有清晰层级、想看跨层汇流 | 层级捆绑 | 04 光纤束 / 08 双曲空间（focus+context） |
   | 稠密图、连线成一团乱麻 | 矩阵 | 05 星阵邻接矩阵（稠密图首选） |
   | 确定性可复现、可比较布局 | 弧/弦 | 06 结构之弦（Hive⇄Arc） |
   | 宏观看哪两个领域绑得最深 | 弧/弦 | 10 关系之环（chord，宏观聚合视角） |

3. **规模判据是硬约束**：先按节点规模排除不可行范式——万级节点只能上 01 GPU 星云（cosmos.gl），数百节点才轮到 SVG/3D 范式；上千条边的 SVG per-edge 渐变会卡死，该改 canvas。
4. **校验→修复→重试**：选定后若用户看画廊觉得不对，回到第 1 步重新点名，不硬推。

## 反模式

- ❌ 替用户定审美：不弹画廊直接挑一个"我觉得好看的"——用户明确要选择权在自己。
- ❌ 无视规模判据：数百节点也敢上 cosmos.gl 全家桶，或万级节点硬用 SVG 连线图。
- ❌ 上千条边还用 SVG per-edge 渐变——数百条可接受，上千条应改 canvas。
- ❌ 默认耦合：用户在做别的事（构建图谱/建库）时，未经点名主动推荐本包的可视化。
