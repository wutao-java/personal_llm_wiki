# 搭三层编译闭环 + self-wiring 建图

## 何时使用

要把一批零散资料（笔记、文档、会议记录、多源材料）组织成可读、可互链、可治理的 wiki 或知识图谱，
而不是切块塞进向量库当机器索引时。核心是"编译执行"取代"解释执行"：一次编译沉淀产物，多次查询直接命中。

## 核心流程

给方案时先一句话点明范式（用户常见误解就在这）：这是**编译执行**——一次编译沉淀可读产物、多次查询直接命中、
可审计可治理；**不是**把原文切块塞向量库当黑箱索引（那是解释执行：临时综合、不可审计、改源即漂移）。

编译式 RAG 只有三层结构、三个操作、两个特殊文件。照此建库即可。

**三层结构（谁拥有什么、谁能改什么）**
1. 规则层 `CLAUDE.md`：人类撰写的 schema——页面命名约定、链接语法、页面类型（如 concept/system/debate）。编译器必须先读它再动手。
2. 源层 `raw/`：源真相，只读，编译过程一字不改（红线，见约束能力）。
3. 产物层 `wiki/`：编译产出的互链页，机器可再生。

**两个特殊文件**
- `index.md`：导航入口，查询先看它定位相关页。
- `log.md`：变更日志，记录每次编译改了什么。

**三个操作**
- Ingest（编译）：读 `raw/` 全部源，在 `wiki/` 产出固定文件名的互链页（用 `[[slug]]` 互链），更新 `index.md` 与 `log.md`。用固定 slug，不要每次随机起名，否则互链断裂无法治理。
- Query（查询）：只读 `wiki/`，先看 `index.md` 导航，命中编译产物作答——不重新通读 `raw/`。给 agent 只读工具（Read/Grep），结构上保证不改产物。
- Lint（校验）：核对链接完整性、悬空边、命名规范。

**编译产物形态标准（Ingest 的验收线——达不到就不叫"编译"，叫"复印"）**

"编译"是把源材料**按知识形态重组**，不是逐文件搬运。每次 Ingest 的产物必须同时满足三层：

1. **结构**：知识页平铺 `wiki/`，**页的划分按知识单元（概念 concept / 系统 system / 争议 debate 等类型），
   不与源文件 1:1 对应**——3 篇源通常编译出的是"1 个概念页 + 1 个系统页 + 1 个争议页"这类跨源重组，
   而不是 3 个对应页。页面类型遵循规则层 `CLAUDE.md` 的 schema。**一切新文件只落 `wiki/`**（含实体存根页），
   `raw/` 一个字节不改、一个文件不增。
2. **内容**：每页 = frontmatter（`title` / `type` / `sources` / `updated`）+ **从多篇源提取、综合出的结论性正文**；
   `sources` 字段回指来源文件。把源文正文抄一遍再加个头，不是编译产物。
3. **关联**：页与页之间用 `[[slug]]` 互链形成网络——**互链总数 > 0 且每条指向真实存在的页**；
   `index.md` 按 type 分区列出所有页，**每页配一行摘要 + 链接**（查询导航靠它）。

自检一票否决项：`wiki/` 页数 == `raw/` 源数且文件名一一对应、页内正文与某篇源大面积相同、全库 `[[]]` 数为 0、
index.md 只有文件名没有摘要——任意一条命中，本次 Ingest 推倒重做。

**self-wiring 零 LLM 建图（GBrain 路线）**
当要把 wiki 升级成可查询的知识图谱时，用 GBrain 的 self-wiring：不抽实体，而是纯正则解析人写好的 `[[目录/slug]]` wikilink 建有向边，零 LLM、零成本、可溯源。
- checklist（复制进回复逐项打勾）：
  - [ ] 语料每处跨页引用都写成带目录前缀的 `[[people/alice-chen]]`（前缀红线见约束能力）
  - [ ] `gbrain import <目录> --no-embed` 把 wiki 导入 brain
  - [ ] `gbrain extract links` 抽边（文件系统语料用 `--source fs --dir`，库内页用 `--source db`）
  - [ ] `gbrain stats` / `gbrain link-sources` 核对边数与 wikilink 数一致——缺边即回查前缀
  - [ ] `gbrain backlinks <slug>` / `gbrain graph-query <slug>` 验证边可双向溯源

**校验环（每次 Ingest 后必跑）**：改源 → 重编译 → 用 git 对照：`raw/` 零 diff、`wiki/` 从空长出产物、边数对得上。不通过就回到对应步骤修复再重试。

## 反模式

- ❌ **raw/ 文件逐个平移到 wiki/、只加个 frontmatter 就叫编译**——1:1 复刻没有提取重组、没有互链，
  后续检索必然大面积落空（实测事故形态：页数与源数相同、正文照抄、`[[]]` 为 0）。
- ❌ 把编译过程的任何新文件（存根页、中间产物）写进 `raw/`——源层只属于人类，产物一律落 `wiki/`。
- ❌ 把 `raw/` 原文直接切块塞向量库当索引就算完——那是"解释执行"（临时综合、难审计、难沉淀），不是编译式 RAG。
- ❌ Ingest 时让 agent 自由起随机 slug——固定文件名才能稳定互链，随机 slug 会让链接指向漂移、无法治理。
- ❌ Query 时重新通读 `raw/` 全部原料再临时归纳——放弃了编译产物，等于没编译，成本和不确定性都回来了。
- ❌ 把 DSPy 的 "compiled RAG"（编译提示词/权重）当成本能力的编译——同名异义，本能力编译的是**知识产物**。
