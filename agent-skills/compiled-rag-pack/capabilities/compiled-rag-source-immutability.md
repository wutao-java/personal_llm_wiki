# 源不可变 + 源变必重编译 + wikilink 前缀（红线）

## 何时使用

任何编译式 RAG / LLM Wiki / GBrain 的编译（Ingest）或查询（Query）任务，动手前先读、全程守。
这三条红线决定编译产物是否可信、可治理——越线的失败往往是**静默的**（答案照旧、图里缺边），不报错却是错的。

## 核心红线

**红线一：源层 `raw/` 一字不改、一件不增**
- 编译与查询绝不写 `raw/`：既不修改已有文件，也**不新建任何文件**——实体存根页、中间产物、索引，一律只落 `wiki/`。
- 查询只给 agent 只读工具（Read/Grep），不给 Write/Edit——从工具层面就改不了产物。
- 验证（两条都要，缺一不可）：
  - `git diff --stat -- raw/` 无输出 = 已有文件零改动；
  - `git status --porcelain -- raw/` 无输出 = 零新增文件（git diff 看不见未跟踪的新文件，必须补这条）。
  任一有输出即越线，回滚/移走。

**红线二：源变必重编译，否则答旧值**
- 编译式 RAG **不会自动同步**。改了 `raw/` 不重新 Ingest，查询命中的还是旧编译产物，会"答旧值"。
- 现象链（亲手验证）：改文档 → 不重编译再查（仍旧值）→ 重编译再查（才是新值）。
- 铁律：任何源文档变更后，先 `gbrain import` / 重跑 Ingest，再查询；用 `log.md` 记录本次编译。
- 处置"答旧值"时顺手做两件事排除并发问题：`git diff --stat -- raw/` 自证这次只有你改的那处、
  源层没被编译过程误改；重编译后跑 `scripts/verify_source_immutability.py` 做完成后自检。

**红线三：wikilink 必带目录前缀，否则静默少边**
- 裸 `[[slug]]`（无目录前缀）在 `--source db` 抽边模式下建 **0 条边**，图谱静默缺边、不报错。
- 必须写全前缀：`[[people/alice-chen]]`、`[[companies/nexaflow]]`。
- 写入即重连：`gbrain put <slug>` 会立即重抽该页链接、对比新旧边集合、删悬空边建新边——看 `auto_links` 的 `removed`/新增确认。

## 校验环（任务完成后必过，不合格先修再交付）

复制进回复逐项打勾：
- [ ] `git diff --stat -- raw/` 空 → 已有源文件零改动（有 diff 立即回滚源层）
- [ ] `git status --porcelain -- raw/` 空 → 源层零新增文件（新文件出现在 raw/ 即越线，移到 wiki/ 或删除）
- [ ] 改过源后已重编译，且查询返回的是新值（不是旧编译产物）
- [ ] `grep -ro '\[\[[^]]*\]\]' <语料目录>` 抽出的 wikilink 全部带目录前缀，无裸 slug
- [ ] 抽边后 `gbrain stats` / `gbrain link-sources` 的边数与 wikilink 数一致，无静默少边
- [ ] 一键跑 Run `scripts/verify_source_immutability.py <wiki 项目目录>`——红项修完再交付

## 反模式

- ❌ 给 Query agent 配 Write/Edit 工具——结构上就能改 `wiki/` 或 `raw/`，破坏可治理性与可信度。
- ❌ 只跑 `git diff` 就宣布源层干净——diff 对未跟踪的新增文件是盲的，编译器悄悄往 `raw/` 塞新页也显示零 diff。
- ❌ 改完 `raw/` 直接查询就信答案——答的是旧编译产物（"答旧值"），且不报错最危险。
- ❌ 用裸 `[[slug]]` 无前缀 wikilink，然后纳闷"为什么图里没有这条边"——静默少边的根因就在前缀。
- ❌ 把"能查到答案"当验收通过——没跑 `git diff -- raw/` 就无法证明源没被污染，产物可信度存疑。
