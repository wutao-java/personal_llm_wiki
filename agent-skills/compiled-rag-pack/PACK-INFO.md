# 编译式 RAG 包（v1.1.0）

## 这个包是什么

你在把一堆资料做成"第二大脑"、知识 wiki 或知识图谱时装上它，你的 Agent 就按课程的"编译式 RAG"工程标准干活：把资料**编译**成可读可互链的知识网络，而不是切块塞进向量库当黑箱索引。

## 装上后，你的 Agent 能做什么

- **把事做对**：按三层结构（规则层 CLAUDE.md / 源层 raw 只读 / 产物层 wiki）搭编译闭环，用 Ingest / Query / Lint 三操作把散资料编译成互链 wiki，并用 GBrain self-wiring（零 LLM 解析 wikilink）建成可查询知识图谱；还能搭一条 cron/launchd 自动化增量管线，让大脑无人值守地持续吃新数据。
- **不做错事**：自动守住三条红线——源层 raw/ 一字不改、源变必重编译（否则答旧值）、wikilink 必带目录前缀（否则静默少边）；团队多人共用时，把访问控制落在数据库层（不靠大模型自觉），越线即拦。
- **排查故障**：命令 EXIT:0 却结果不对时，按"症状→根因→修复"表定位这类静默失败——查不到、缺边、sync 不增量、调度器被杀 EXIT:143、exFAT 不可写、维度不匹配、隔离泄漏。
- **知道做没做好**：干完活一键跑验收脚本——源不可变自检、管线健康判读（embeddings 100%）、隔离零泄漏核验（source_id 越界即 FAIL），红项先修再交付。
- **选得对**：传统向量 RAG / 编译式 wiki / GBrain 图谱三元选型，以及编译 wiki + 向量 RAG 混合架构选型，按"可治理性/跨界质量"而非"省成本"给推荐，避免为省钱误选却更贵。

## 怎么用

1. **安装**：把本包目录放入 `.claude/skills/`（Claude Code）或 `.agents/skills/`（Codex）。
2. **触发**：正常干活即可，遇到本包场景 Agent 自动调用；也可以直接说——
   - "把这批笔记编译成一个可读可互链的 wiki / 第二大脑"
   - "我改了源文档，为什么查询还是答旧值？编译式 RAG 会自动同步吗？"
   - "传统向量 RAG、编译式 wiki、GBrain 图谱，我这个需求该选哪个？"
   - "搭一条 cron/launchd 自动化增量管线，让大脑无人值守吃新数据"
   - "稳定架构文档 + 每天新增工单，混合 wiki + 向量 RAG 怎么设计？"
   - "团队多人共用大脑，怎么按 source 隔离不让销售看到 HR 绩效？"

## 30 秒见效

复制这句话给你的 Agent：

> 把 raw/ 里三篇资料编译成互链 wiki，然后我改一篇源文档但先不重编译，你直接查询会怎么样？

装包前它会直接把三篇塞进上下文临时归纳、改源后照答旧值也不自知；装包后它会声明 raw/ 只读、指出"不重编译会答旧值"、重编译后才给新值，并用 `git diff -- raw/` 自证源未被改。详见 [quick-run.md](quick-run.md)。
