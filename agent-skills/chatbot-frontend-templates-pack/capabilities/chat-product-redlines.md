# 产品红线 · 基线模板 ≠ 演示馆（动手前先读）

## 何时使用

改这套对话模板的视觉、加交互、或收到"做炫酷点"之类诉求之前——动手前先读。这些是会导致整轮
返工或"一眼 demo"的红线，全程生效。

## 首要红线：基线模板 ≠ 演示馆

第一版做成了星图馆式炫酷展览馆，被推翻重做。**"产品模板"和"效果演示"是两种东西**：模板要
**克制中性、像真产品**（对标 ChatGPT / Perplexity 的质感），渐变霓虹 / 粒子背景 / 装饰堆砌只适合
展示场景。本包与 knowledge-graph-viz-pack（星图馆，越炫越好）视觉定位**相对**——这里越像真产品越好。
收到"加粒子背景 / 霓虹渐变 / 做酷炫点"的诉求：**拒绝并解释**，给"对标某真实产品 + 精确结构描述"的
产品级路径替代。

## 红线清单（逐条硬约束）

1. **不做演示馆**：禁渐变霓虹 / 粒子背景 / 装饰堆砌。强调色只给**一个**（accent），只用在"最该点的
   东西"上（发送键 / 引用角标 / 高亮），不到处撒。
2. **禁含糊词**：指令与自我发挥里不出现"高级点 / 现代点 / 好看点"——用**精确 hex + 对标产品名 +
   结构描述**说话。视觉全走 CSS 变量 token，**裸 hex 散落即违规**（可跑 scripts/check_template_integrity.py 抓）。
3. **按钮地板**：演示环境里"点了没反应的按钮"一律不许存在——统一绑 toast 说明"此处接你的真实逻辑"，
   需要静默的标 `data-silent`。
4. **craft 底线**（每页交付前过一遍）：空态有引导不留白屏 · hover 全部有态变 · 操作有即时反馈
   （toast / 流式 / 状态翻转）· 数字与时间戳一律 mono · **区块间距 > 区块内间距**。

## 落地流程（校验→修复→重试）

1. 动视觉前：确认颜色全走 `var(--x)`，不新增裸 hex。
2. 加按钮/交互后：确认每个可点元素要么有真实反馈、要么绑 toast、要么标 `data-silent`。
3. 交付前机检：`python3 scripts/check_template_integrity.py <页面>` 抓裸 hex / 死按钮 / 骨架残缺 /
   引号截断；红项改到过再交付（校验器自身可 `--selftest` 自证）。

## 反模式

- ❌ 把对话前端做成炫酷展览馆（渐变霓虹 / 粒子）——与本包定位相反，必被推翻。
- ❌ 用含糊词"做高级点 / 好看点"自我发挥、裸 hex 散落——过不了机检，深色主题必失配。
- ❌ 留"点了没反应"的死按钮、空态白屏、hover 无态变——craft 底线不过，一眼 demo。
