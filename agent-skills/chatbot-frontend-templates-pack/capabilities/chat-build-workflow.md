# 建站工作流 · 从三决策到逐页建（防方向性返工）

## 何时使用

要从零把一整套对话产品前端做出来、想按正确顺序开工避免方向性返工时。只搭好一页的骨架
→ 走 chat-shared-layer-contract；只选一个形态 → 走 chat-template-selection；接真后端
→ 走 chat-backend-wiring。本能力讲**全流程的顺序**。

## 核心流程（顺序固定，别跳步）

1. **三决策先锁**（含糊就 AskUserQuestion 摆预览让用户拍板——第一版"展览馆 vs 产品级"就是靠这个纠偏的）：
   - 视觉基调：本套 = **正经产品级**（对标 ChatGPT/Perplexity），不是展示级。
   - 每页布局原型：基线三段式 or 特殊（如 05 双栏画布）。
   - 质感档位：**适度**——流式 / 转圈 / toast，不堆装饰。
2. **index 先行**：先做选型画廊（`assets/index.html`：卡片 = 精确布局线框图，accent 虚线标出差异区），
   **清单确认后再逐页建**，避免做到一半发现布局方向错、整轮重来。
3. **共享层先立**：token + 骨架 + CT 一次立好（见 chat-shared-layer-contract），
   每页只写差异面板与 mock，八页才保持一致且单页 200 行级。
4. **逐页建**：按选定形态套骨架、写差异区、注册 `CT.demoReply`、做入场流式。
5. **mock 要专业密度**：真实数字、口径冲突标注、时间戳——假数据一眼假，模板就一眼 demo。
6. 每页交付前过 chat-product-redlines（红线）+ chat-dual-theme-acceptance（明暗双主题验收）。

## 反模式

- ❌ 不先锁三决策直接开写——"展览馆 vs 产品级"方向性返工（第一版就是这么被推翻重做的）。
- ❌ 不 index 先行直接逐页建——做到一半发现布局方向错，整轮重来。
- ❌ mock 用占位假数据（"示例数据 1/2/3"）——成品一眼 demo，失去"产品级"意义。
