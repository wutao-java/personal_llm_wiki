# 明暗双主题验收闭环（完成后必过）

## 何时使用

一页对话产品前端改完、要判断能不能交付时。还在搭建/选型阶段 → 走对应能力。本能力是**交付前
必过的验收闭环**，不看渲染就宣布完成 = 没做完。

## 核心流程（Playwright 闭环，顺序固定）

1. 起本地服务用 **http** 打开页面（`python3 -m http.server`；不要 file:// 双击——主题偏好
   `localStorage['ct-theme']` 在 file:// 与 http:// 不互通）。
2. `navigate` → **等长模拟跑完再截图**：03 / 06 / 08 的模拟要跑 **8~16 秒**，`wait_for` 给足时间；
   **截半程会误判"没渲染"**。
3. 截图 + 查 `console_messages`：**零 console error 是硬标准**，有报错先修再继续。
4. **交互真点**（不是只看首屏）：按模板点该点的——引用角标定位（02）/ 步骤卡展开（03）/ tab 与
   单选提交（04）/ 版本切换与圈选（05）/ 进度卡（06）/ 对比分支采用（07）/ 团队编排（08）。
5. **明暗主题各抽查**：点主题按钮切到另一套，两套都截图看 token 有没有失配。
   （主题按钮显示的是"将切换到"的**目标态**；若你用 JS 直接改 `dataset.theme` 会绕过 label 更新，
   肉眼验证时别把它误判成 bug。）
6. **不过就改，改完重来**——回到第 1 步再跑一遍闭环。

## 验收硬标准（三条缺一不过）

- 零 console error；
- 该点的交互真响应（有 toast / 流式 / 状态翻转，无死按钮）；
- **明暗双主题**都渲染正常、token 不失配。

## 反模式

- ❌ 只看首屏截图就宣布"完成"——白屏 / 过曝 / 半程状态要用户自己发现。
- ❌ 长模拟（03/06/08）截半程——误判"没渲染"，把跑到一半的中间态当 bug。
- ❌ 只验浅色主题不切深色——深色下 token 失配漏检。
